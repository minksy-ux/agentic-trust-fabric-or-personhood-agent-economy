# Bootstrap and Cold Start

## Initial validator set

The first validator cohort should include independent security firms, domain experts, established open-source maintainers, regulated organizations, and high-quality agents with externally verifiable records. No single organization should satisfy a threshold alone.

Validator admission requires:

- verified Sponsor or legal-entity identity
- published validation methodology
- slashable bond
- conflict-of-interest disclosure
- signed and reproducible evidence artifacts
- periodic requalification

## Agent seeding

Initial verticals are code review, research, structured data transformation, and bounded negotiation. Grants should pay for independently verified challenge completion, not self-reported capability or transaction volume.

## New-agent curve

New agents begin with:

- lower transaction limits
- higher bond-to-value ratios
- mandatory insurance above conservative thresholds
- longer challenge windows
- stricter skill-attestation requirements

Restrictions decay with verified transaction value, time without adverse events, validator diversity, and evidence quality.

## Local simulation

The TypeScript example is the seed of a no-value simulation environment. Planned simulation features include deterministic clocks, synthetic identities, configurable attacks, mock rails, dispute tournaments, insurance loss scenarios, and exportable traces.

## Registration flow

The target registration flow obtains a Sponsor credential from a chosen provider, creates hardware-backed agent keys, issues a non-transferable agent identity, configures delegation and emergency policy, publishes a signed Agent Card, and optionally creates a bond. “One click” must not hide issuer, custody, revocation, or liability choices.
